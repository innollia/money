# 수익 탐색 실행 기준 v1.2

기준일: 2026-10-18. 자료/원본_v1.1_과거실사.txt의 v1.1 계획을 유지하며 아래 실행·중단 기준을 추가한다. 과거 실사 결과와 이번 사용자 평가 자체는 외부 사실의 최신 검증이 아니다.

## 유지 기준

| 항목 | 기준 |
|---|---|
| 수익 | 월 순수익 5만~50만 원 우선, 100만 원 미만 |
| 자본 | 0원 우선, 예외는 회수 근거와 별도 승인 |
| 시간 | 주 2~6시간 비교 가정. 사용자 확정 가용시간 아님 |
| 시간 범위 | 조사·지원·영업·대기·상담·작업·수정·정산·이동 |
| 장소 | 한국 재택 우선, 잠실새내역 출발 지역 차선 |
| 사용자 조건 | 성인·고교 재학을 기준으로 자격 검사. 장비·경력·영어·계정 보유 임의 가정 금지 |
| AI | 계약상 허용 여부 먼저 확인 |
| 정산 | 한국 수령·수수료·최소 출금·지연·작업월/입금월 구분 |
| 범위 | A 빠른 현금화 / B AI 활용 / C 반복 수익, 8개 시장 유지 |

발굴 40~60, 기본 검증 15~20, 심층 6~8, 실험 3~5는 탐색 목표다. 전수 발굴을 개별 후보의 소규모 실험 준비보다 앞선 필수 대기 조건으로 쓰지 않는다. 기준 미달을 개수로 보완하지 않는다. 전체 탐색 목표 미달은 그대로 보고한다.

## 검증 게이트

A 실제 활성 모집·고객의 유료 수요 → B 가입·자격·약관·한국 출금 → C 작은 작업 재현 → D 실제 지원·고객 반응·배정 → E 첫 거래·현금 수령.

각 조건은 통과/탈락/미확인, 후보는 통과/탈락/보류/재검증으로 기록한다. 기술 외주 등은 실제 수요·신규 진입·고객 확보 비용·실행 가능성·경쟁 우위도 따로 확인한다. A/B가 미확인이면 통과 후보나 수익 확정으로 승격하지 않는다. C 이전 가격·작업시간 확정 금지. 근로의 C는 무료 실근무를 요구하지 말고 공개 업무 요건과 준비 가능성을 확인한다.

필수 조건 통과 후에만 100점 평가: 월 순수익 25, 실질 시간당 순수익 20, 첫 입금 가능성 20, 유연성 15, AI 우위 10, 반복성 10. 확률·점수의 근거가 부족하면 평가 보류. 실험은 경쟁 우위를 확인하기 위한 가설 검증일 수 있으나 미통과 게이트를 숨기지 않는다.

## 추가 조사 중단

검색 전 `이 답이 순위·탈락·다음 행동 중 무엇을 바꾸는가`를 한 줄 기록한다. 어느 것도 바꾸지 않으면 검색하지 않는다.

- 계정별 보수·지급수단·선발·실제 배정: `사용자 확인 필요`. 같은 공개 질문 반복 검색 중단.
- 공고 삭제·접근 실패: 원본 1회와 공식 대체 경로 1회 확인 후 `접근 실패/현재성 미확인`. 공고 종료로 단정하지 않는다.
- 미충족 자격·시간·초기 비용이 명확하면 탈락 또는 조건부 보류. 비슷한 광고로 결론을 뒤집지 않는다.
- 공개 확인이 끝났으면 `다음 단계 준비`로 전환한다. 계정 확인이 남으면 완료라고 표시하지 않는다.
- 이번 차수 공수 상한은 작업 문서에 따른다. 이는 조사 효율 기준이며 필수 검증 생략의 근거가 아니다.

## 성과 기준

새 사실 수만 세지 않는다. `새 사실 → 변경된 판정 → 가능해진 행동 → 실행 증거`를 남긴다.

공고·프로그램 식별자가 있는 개별 후보만 센다. 플랫폼 이름·서비스 아이디어·중복 공고는 제외한다. 자료 등급 A/B/C/D는 원자료가 실제로 주장하는 범위에만 부여한다. 이번에 열지 않은 과거 자료에 새 A등급을 부여하지 않는다.

## 근로 기준선과 현금 기록

일반 근로를 동일 시간 범위로 비교한다. 실질 시급 = (수령액 - 직접비용) / 전체 투입시간. 세금 미확인이면 세전이라고 표시한다. 아직 입금되지 않은 금액은 현금 실적으로 세지 않는다. 투입시간이 있으면 수입 0인 실패도 보존한다.

외주가 근로 기준선보다 낮으면 우선순위를 낮춘다. 예외는 반복 계약·재사용 자산 등 구체적인 장기 이점과 이를 확인할 실험이 있을 때만 기록한다. 근로 기준선도 미확인이면 금액 순위를 확정하지 않는다.

## 현실 실험 승인

준비 산출물에는 대상·정확한 행동·사용자 입력·금전 상한·전체 시간 상한·중단 조건·관측 항목을 넣는다. 가입/인증, 지원/외부 연락, 판매 게시, 결제/계약을 구분해 승인을 요청한다. 사용자에게 자료를 보내기 전까지 가능한 공개 검증·양식·문의 초안은 완료한다. 실제 연락이나 지원은 별도 승인 전 수행하지 않는다.
