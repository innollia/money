# 보고서 제출 규격

보고서는 AI 회수용 작업 데이터다. 도입·격려·반복 요약·장식 금지. 원자료를 읽지 않았으면 명시한다.

## 파일

- 01: 보고서/01_근거리근로.md
- 02: 보고서/02_재택AI작업.md
- 03: 보고서/03_기술외주.md
- 04: 보고서/04_현실실험설계.md
- 05: 보고서/05_재택계정.md

같은 작업 재실행 시 기존 보고서를 덮어쓰지 말고 `_r2` 등으로 구별한다. 다른 파일은 수정하지 않는다.

## 최소 내용

1. 작업 ID / 확인일·시간대 / 읽은 기준 커밋 / 완료·부분완료·차단 / 소요시간(미측정이면 미측정).
2. `후보 ID | 구체적 모집·의뢰 | 확인 사실 | 원본 URL·절/공고 ID | 게시·수정일 | 확인일 | 자료 유형·등급 | A/B/C/D/E 상태 | 판정 | 미확인 | 다음 행동`.
3. `새 사실 | 바뀐 판정 | 가능해진 행동 | 실행 여부·증거`.
4. 사용자 확인 필요 항목. 질문별로 확인 화면·필요한 비민감 값·답에 따른 분기를 기재.
5. 즉시 실행 가능한 준비물·미완료·중단 사유. 지원·연락·게시·결제·입금은 별도 실적 집계.

주요 주장마다 해당 주장을 뒷받침하는 직접 URL 필요. 홈페이지로 약관 조항을 대신하지 않는다. 단일 성공 사례는 성공률이 아니다. 자료의 접근 실패를 주장 반증으로 쓰지 않는다.

## GitHub 제출

작업 시작 시 최신 main을 확인한다. 보고서만 커밋한다. push 직전 원격 변경을 가져와 다른 작업자의 결과를 보존한다. 충돌이 나면 자기 보고서만 해결하고 공통 파일은 변경하지 않는다. force push·브랜치 삭제 금지. 직접 push 권한이 없으면 작업 브랜치와 PR 또는 사용자 전달용 보고서를 준비하고 미업로드 상태를 명시한다.

사용자에게 `작업 ID | 보고서 GitHub 링크 | 커밋 SHA | 완료/부분완료/차단 | 다음 사용자 행동`을 반환한다. 업로드 실패는 완료가 아니다. 보고서 링크를 주 에이전트에게 자동 전송하지 않는다. 사용자가 전달한다.
