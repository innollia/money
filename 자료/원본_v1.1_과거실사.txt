# 실행·기록 문체 규칙 (최우선)

- **사람이 읽는 문서는 완전 최종 보고서뿐.** 중간 조사·메모·검색 기록·후보 목록·단계 보고는 AI 간 전달용 작업 데이터로 취급.
- **중간 출력:** 구어체·미사여구·도입/맺음말·반복 요약·격려·장식적 제목·과도한 서술 금지. `대상 | 확인 사실 | 근거 URL·일자 | 판정 | 미확인 | 다음 검증` 등 최소 필드 사용. 조사 중간에는 사실·숫자·조건·제약·판정만 짧게 기록. 표도 정보 절약에 유리할 때만 사용.
- 중간 과정에서 사용자에게 진행 내용을 알려야 할 경우에도 같은 형식 적용. 근거 없음을 숨기려고 문장을 늘리지 않음. 정보 누락을 위해 축약하지 않음.
- **최종 출력:** 사용자에게 제출하는 최종안만 읽기 쉬운 자연스러운 설명·구조화·비교·추천 허용. 검증 수준·근거·불확실성은 유지.
- 문체 지침은 내용 삭제·검증 생략·임의 판단·보고 누락을 허용하지 않음. 아래 계획서에 남아 있는 구어체는 기존 계획 원문이므로, 조사 시 중간 출력 문체의 예시로 따라 하지 말 것.
- **자료 우선순위:** 계획서 v1.1의 기준·검증 게이트·현재 상태 > 뒤에 첨부한 1~3차 과거 조사. 과거 조사에서 제시된 `통과`, `확정`, `우선순위`, `실험 가격`은 v1.1을 통과한 현재 결론으로 취급하지 않음.

# 월 100만 원 미만 수익 탐색 실행계획 v1.1

**2026년 10월 18일 기준 · 목표: 적은 시간으로 실제 현금 수익 확보**

**개정 목적:** v1.0의 조사 방향·조건·시장 범위·점수 체계를 유지하면서, 이전 조사에서 발생한 검증 단계 생략, 공급자 중심 조사, 경쟁 강도 과소평가, 근거 없는 후보 확정 문제를 수정한다.

**문서 실행 조건:** 이 계획서는 과거 대화나 사용자 장기기억이 없는 새로운 AI 에이전트가 단독으로 실행할 수 있어야 한다. 이 문서에 명시되지 않은 이전 조사 결과, 사용자의 능력, 지원·판매 이력을 사실로 가정하지 않는다.

조사 방향은 3개 트랙 병렬 탐색으로 확정하겠어.

### A. 빠른 현금화

소액 알바·설문·테스트·건당 작업

### B. AI 활용 수익

자동화·코딩·편집·기술 서비스

### C. 반복 수익

유지보수·정기 의뢰·디지털 상품

A는 당장 돈이 필요한 상황을, B는 AI 활용 경험이라는 자산을, C는 매달 돈을 벌기 위해 계속 새로운 일감을 찾는 부담을 줄일 가능성을 검증하는 트랙이야.

### v1.1 추가 — 시간과 수익의 해석

- 주당 2~6시간에는 실제 작업뿐 아니라 고객 확보, 지원서 작성, 대기, 상담, 수정, 정산 처리, 이동시간을 포함한다.
- 수익은 광고상 보수가 아니라 실제 수령 가능한 금액을 기준으로 한다.
- 플랫폼 수수료, 환전 비용, 유료 도구 비용, 교통비 등 직접비용을 공제한다. 세금까지 확인할 수 없으면 세전 금액임을 명시한다.
- 작업을 완료한 시점과 실제 입금된 시점을 구분한다.
- 특정 월에 발생한 매출을 해당 월의 현금 수입으로 자동 계산하지 않는다.
- 사용자에게 없는 자격·학력·장비·경력·포트폴리오를 임의로 가정하지 않는다. 확인할 수 없는 조건은 `미확인`으로 유지한다.

### v1.1 추가 — 후보 개수 산정 규칙

**플랫폼 이름이나 사업 아이디어만으로 검증된 후보 1개를 채웠다고 계산하지 않는다.**

후보는 최소한 다음 중 하나를 식별할 수 있어야 해.

- 특정 일자리 또는 프로젝트 모집 공고
- 구체적인 업무와 대가가 명시된 실제 구매 요청
- 판매 이력이 확인되는 구체적인 상품·서비스
- 공식적으로 참여·정산 경로가 존재하는 특정 유료 프로그램

`Discord 봇 외주`, `재택 알바`, `Roblox 상품 판매` 같은 표현은 시장 분류 또는 탐색 키워드이지, 그 자체로 검증된 개별 후보가 아니야.

예비 아이디어는 별도 기록할 수 있지만, 검증 후보 개수에는 넣지 않아.

서로 같은 일감을 중복 게시한 공고도 하나로 계산해.

### 3-A. v1.1 신설 — 수요와 경쟁 검증

이전 조사에서는 판매자와 판매 상품이 존재한다는 사실을 확인한 뒤, 신규 진입자의 수익 가능성까지 높게 평가하는 오류가 발생했어.

앞으로 기술 외주·업무 대행·디지털 상품·지속계약형 서비스에는 다음 조사를 추가해.

**① 실제 구매 수요**

- 고객이 직접 작성한 구매 요청 또는 구인공고가 존재하는가?
- 거래 후기에서 실제 유료 거래를 확인할 수 있는가?
- 단발성 수요인가, 반복적으로 발생하는 수요인가?
- 어느 가격에 실제 거래가 이루어졌는가?
- 판매자가 공개한 가격과 실제 결제 금액을 구분할 수 있는가?

**② 경쟁 및 신규 진입 가능성**

- 동일 서비스를 제공하는 판매자는 얼마나 많은가?
- 저가 경쟁이 심한가?
- 상위 판매자에게 거래가 집중되어 있는가?
- 신규 판매자 또는 리뷰가 적은 판매자도 실제 거래를 성사시키는가?
- 고객은 왜 기존 판매자가 아닌 신규 판매자를 선택할 수 있는가?
- 고객을 확보하려면 광고비, 플랫폼 수수료, 견적 발송 비용, 영업 시간이 얼마나 필요한가?

**③ 차별화 가능성**

- 경쟁자도 같은 AI 도구를 사용한다고 가정했을 때 우위가 남는가?
- 특정 고객층이 겪는 문제를 더 저렴하거나 빠르게 해결할 수 있는가?
- 고객에게 전달되는 결과가 검증 가능한가?
- 자동화·기존 코드·재사용 가능한 작업물이 실제로 시간을 절감하는가?
- AI를 쓰지 않더라도 운영 경험, 전문성, 고객 접근성 등 다른 우위가 존재하는가?

**④ 공급과 수요의 불균형**

판매자가 많다는 사실만으로 레드오션을 확정하지 않고, 구매자가 많다는 사실만으로 블루오션을 확정하지 않아.

신규 판매자가 확보할 수 있는 수요의 크기와 경쟁 압력을 함께 평가해.

정량 통계가 없으면 `경쟁이 심해 보인다`, `신규 진입이 쉬워 보인다` 등의 인상을 확정 사실로 바꾸지 않고, 실제 관측 근거와 함께 가설로 기록해.

**판정 규칙**

기술 외주나 디지털 상품에서 판매자 게시물만 발견하고 고객 측 유료 수요 또는 거래 증거를 확보하지 못했다면 `수요 미검증`으로 남겨.

거래 증거가 있더라도 신규 진입 가능성이 확인되지 않았다면 `시장 수요 확인·신규 진입 미검증`으로 분류해.

이 상태에서는 특정 상품을 최종 추천하거나 가격을 확정하지 않아.

### 3-B. v1.1 신설 — 근거 보존 및 신뢰도

모든 주요 사실은 새 에이전트가 다시 검증할 수 있도록 다음 정보를 남겨.

- 원본 URL 또는 공고 식별자
- 조사한 날짜
- 원본 게시·수정 날짜(확인 가능할 경우)
- 자료의 종류: 공식 공고 / 공식 약관 / 구매 요청 / 거래 후기 / 사용자 경험담 / 추정
- 확인한 구체적인 내용
- 확인하지 못한 내용
- 근거가 해당 주장에 충분한지 여부

근거 수준은 아래처럼 구분해.

| 등급 | 의미 |
|---|---|
| A | 공식 약관·모집공고 또는 검증 가능한 직접 거래 자료 |
| B | 복수의 독립적인 거래·참여 사례로 뒷받침됨 |
| C | 개별 후기, 단일 사례, 제한적인 간접 증거 |
| D | 판매자 광고, 검증되지 않은 주장, 모델의 가설 |
| 미확인 | 자료 부재 또는 검증 불가능 |

A등급 자료라도 그 자료가 증명하는 범위를 벗어나면 안 돼. 공식 플랫폼이 한국에서 가입 가능하다고 밝히는 것은 한국 참가자에게 충분한 유료 작업이 배정된다는 증거가 아니야.

판매 후기와 판매자 광고를 독립적인 두 근거처럼 중복 계산하지 않아.

## 4. 필터링과 수익성 평가

### 후보 압축 과정 · 목표 개수

| 단계 | 목표 개수 |
|---|---:|
| 발굴 | 40~60 |
| 기본 검증 | 15~20 |
| 심층 분석 | 6~8 |
| 실험 후보 | 3~5 |

목표 개수일 뿐, 기준 미달 후보를 억지로 채우지 않아.

### 1차: 필수 조건 검사

실재하는 모집·거래 경로가 있는지, 한국에서 가입·출금할 수 있는지, 학교와 병행 가능한지, 선입금 없이 시작할 수 있는지 확인해. AI 사용이 제안되는 작업은 계약상 허용되는지도 검사하겠어. AI를 사용할 수 없는 정상적인 알바는 탈락시키지 않고 별도 비교군으로 유지해.

### v1.1 추가 — 필수 조건의 통과 방식

필수 조건은 다음 세 가지 상태로 기록해.

- **통과:** 해당 조건을 뒷받침할 근거를 확인했음.
- **탈락:** 해당 조건과 명백하게 충돌하는 근거를 확인했음.
- **미확인:** 근거 부족 또는 확인 실패.

미확인을 통과로 취급하지 않아.

또한 조건 검사가 불가능한 후보를 단순히 좋은 점수로 보완하지 않아. 특히 지원 자격, 정산 가능 국가, 선입금 요구, 시간 제한처럼 실제 참여를 막는 조건을 우선해.

### 2차: 점수 모델

각 후보는 다음 기준으로 100점 만점 평가하겠어.

| 평가 기준 | 배점 |
|---|---:|
| 예상 월 순수익 | 25점 |
| 실질 시간당 순수익 | 20점 |
| 첫 입금 가능성 | 20점 |
| 시간·장소 유연성 | 15점 |
| AI 생산성 우위 | 10점 |
| 반복 가능성 | 10점 |
| **합계** | **100점** |

추가로 미지급·계약·개인정보 위험에 따라 감점하고, 확인되지 않은 정보에는 높은 점수를 주지 않겠어.

핵심은 광고된 시급이 아니라 첫 달의 기대 순수익이야.

\[
E(M)=P(\text{진입 성공})\times E(\text{작업 순이익}\mid\text{진입 성공})-\text{초기비용}
\]

예를 들어 시급이 높아도 선발 확률이나 일감 공급량이 낮다면 기대수익이 크게 떨어지겠지. 정확한 통계가 없으면 임의로 확률을 확정하지 않고, 비관·기준·낙관 시나리오로 범위를 제시하겠어.

### 4-A. v1.1 신설 — 점수 산정 통제

필수 조건을 통과한 후보만 종합 점수를 산정해.

각 항목은 점수와 별도로 근거 수준을 표시하고, 점수를 계산할 수 없을 만큼 정보가 부족하다면 `평가 보류`로 처리해.

다음 사항을 준수해.

1. 현재 모집공고의 보수와 실제 지급된 보수를 혼동하지 않는다.
2. 상위 판매자 매출을 신규 판매자의 매출 예측에 사용하지 않는다.
3. 신규 고객 확보 가능성이 검증되지 않은 외주의 첫 달 수익을 확정 금액으로 제시하지 않는다.
4. 정산 지연이 있다면 작업 완료월 수익과 현금 입금월 수익을 별도로 계산한다.
5. 선발, 고객 확보, 작업 배정, 검수 통과, 지급 완료 등 서로 다른 확률을 한 단계로 뭉뚱그리지 않는다.
6. 정확한 확률을 모르면 숫자를 만들어 넣지 않는다.
7. 서로 다른 작업 방식의 시간비용을 동일한 기준으로 계산한다.

**비관·기준·낙관 시나리오**도 현실적인 근거가 없으면 수익 금액을 억지로 채우지 않아.

예를 들어 신규 판매자의 첫 달 구매 확률에 대한 자료가 전혀 없다면, `첫 달 0건 가능성`, `1건 판매 시 수익`, `2건 판매 시 수익`을 각각 조건부 결과로 제시할 수 있지만, 이를 기대수익이라고 부르지 않아.

### 4-B. v1.1 신설 — 경쟁 검증 게이트

기술 외주·업무 대행·디지털 상품·지속계약형 서비스는 점수 모델에 들어가기 전에 별도의 경쟁 검증을 통과해야 해.

| 게이트 | 통과에 필요한 근거 |
|---|---|
| 실제 수요 | 유료 구매 요청 또는 확인 가능한 거래 증거 |
| 신규 진입 가능성 | 신규·저실적 판매자의 거래 사례 또는 직접 관측 가능한 진입 경로 |
| 고객 확보 비용 | 수수료, 광고비, 영업시간 등 주요 비용 파악 |
| 실행 가능성 | 필요한 기술·장비·자격과 사용자 조건의 충돌 없음 |
| 경쟁 우위 | 검증 가능한 효율·품질·접근성 우위의 근거 또는 실험 가능한 가설 |

검증 자료가 부족할 경우 `보류`하고 어떤 자료가 부족한지 기록해.

수요가 확인되었다는 이유만으로 나머지 조건을 자동 통과시키지 않아.

레드오션도 무조건 탈락시키지는 않지만, 신규 진입자에게 유리한 구체적인 근거가 없으면 우선순위를 낮춰.

## 5. AI 우위는 별도로 실험

개발·문서·편집·자동화 같은 작업에서는 다음 세 가지 시간을 측정하도록 할 거야.

| 측정 항목 | 의미 |
|---|---|
| 직접 작업 시간 | AI 도움 없이 동일 품질 결과를 만드는 시간 |
| AI 활용 작업 시간 | 프롬프트, 결과 검수, 수정 포함 |
| 추가비용 | API 호출, 소프트웨어, 오류 재처리 비용 |

AI가 30분짜리 일을 5분으로 줄여도, 고객을 확보하는 데 3시간이 걸리면 전체 수익성은 생각보다 낮아져.

또한 다른 판매자도 똑같은 AI 도구를 사용한다고 가정하겠어. 단순 생성물 판매보다 고객 맞춤 설정, 설치, 통합, 유지보수처럼 검증 가능한 부가가치가 있는지 우선적으로 검사할 거야.

### v1.1 추가 — 실험 순서와 생산성 정의

AI 생산성 검증은 **시장성과 참여 가능성을 확인한 후보에 대해서만** 수행해.

시장 수요가 미검증된 서비스를 임의로 만들어 보는 데 많은 시간을 쓰지 않아.

가능하면 동일한 요구사항과 품질 기준으로 직접 작업과 AI 활용 작업을 비교하되, 직접 작업시간을 측정하기 어렵다면 추정치임을 밝히고 생산성 우위 검증을 완료로 표시하지 않아.

AI 생산성 우위는 다음 세 가지를 구분해 평가해.

- **개인 생산성:** 사용자가 AI 없이 수행할 때보다 빠른가?
- **경쟁 생산성:** 다른 AI 활용 판매자와 비교했을 때 우위가 남는가?
- **사업 생산성:** 고객 확보, 상담, 작업, 검수, 사후 대응까지 포함해 전체 시간이 줄어드는가?

AI 사용이 계약상 허용되지 않는 작업에서는 해당 업무를 AI로 수행하는 실험을 하지 않아.

## 6. 조사에서 실제 수익 실험으로 넘어가는 기준

조사만으로는 수익성을 확정할 수 없으므로 다음 기준을 마련하겠어.

| 단계 | 수행 | 통과 기준 |
|---|---|---|
| 검증 A | 실제 구인·구매 수요 확인 | 활성 공고 또는 유료 거래 증거 |
| 검증 B | 가입·자격·약관·출금 확인 | 실제 참여에 치명적인 장애 없음 |
| 검증 C | 소규모 작업 재현 | 요구 품질을 정해진 시간 안에 달성 |
| 검증 D | 최소 규모로 지원·판매 시도 | 지원 접수, 고객 반응, 작업 배정 등 확인 |
| 검증 E | 첫 유료 거래 및 정산 | 실제 현금 수령 확인 |

D와 E는 별도의 현실 실험 단계야. 계획 조사 과정에서 사용자 동의 없이 유료 결제·지원·계약을 진행하지 않겠어.

### 6-A. v1.1 신설 — 단계 건너뛰기 금지

- 검증 A를 통과하지 못한 기술 외주 상품은 검증 C의 본격 제작 대상으로 올리지 않는다.
- 검증 B에 필요한 정보가 없으면 먼저 해당 정보를 조사한다.
- 검증 C 이전에 판매 가격이나 작업시간을 확정하지 않는다.
- 검증 D를 수행하지 않았다면 고객 확보 가능성을 검증했다고 표현하지 않는다.
- 검증 E를 수행하지 않았다면 실제 현금 수익을 확인했다고 표현하지 않는다.

**검증 A는 영역별로 다르게 적용해.**

구직형 서비스는 실제 활성 채용공고로 수요를 확인할 수 있어.

기술 외주와 디지털 상품은 신규 고객이 실제로 비용을 지불하는 시장인지, 신규 진입자의 거래 가능성이 있는지 추가로 검증해야 해.

단순 판매 페이지나 광고 문구는 기술 외주의 검증 A를 단독으로 통과시키는 근거로 사용하지 않아.

### 6-B. v1.1 신설 — 중단·보류 규칙

후보가 기준을 통과하지 못하면 다음 중 하나로 처리해.

- **탈락:** 명확한 자격 불일치, 출금 불가, 비용 대비 낮은 수익 등으로 부적합.
- **보류:** 수익 가능성은 있지만 자료 부족으로 판단 불가.
- **재검증:** 자료가 오래됐거나 원본과 이전 조사 내용이 충돌함.
- **통과:** 근거를 갖춘 다음 단계 진행 가능.

수익성에 관한 근거가 없는데도 조사 목표 개수를 채우려고 통과시키지 않아.

또한 특정 시장이 조사 과정에서 지나치게 경쟁적이라는 사실이 확인되면, 그 시장에서 억지로 차별화 상품을 만들어내지 않고 다른 영역의 후보와 비교해.

## 7. 조사 실행 순서와 작업량

### 조사 작업 일정표

*조사 공수 추정, 확정 소요시간 아님*

**1. 기초자료 및 8개 시장 병렬 조사 · 2~3시간 상당**

노션 기존 조사 재활용, 공식 플랫폼의 모집·거래 수요 확인, 후보 40~60개 수집

**2. 자격·정산·사기·시간 필터링 · 1~2시간 상당**

15~20개로 압축, 출금 불가나 시간 불일치 후보 정리

**3. 수익모델 및 AI 생산성 분석 · 2~3시간 상당**

6~8개를 심층 비교하고 예상 첫 달 수익·실질 시급·불확실성을 계산

**4. 실험 설계 및 최종 후보 확정 · 약 1시간 상당**

가장 작은 비용으로 검증할 3~5개와 우선 실행 순서 결정

**총 조사 공수 추정: 6~9시간**

*실제 지원·수익 실험 시간 제외*

이 조사 자체는 가능한 한 내가 수행하고, 실제 계정 인증이나 포트폴리오 제공처럼 본인 참여가 필요한 과정만 구분하겠어.

### v1.1 추가 — 실행 공정 관리

위 조사 시간은 초기 예상치일 뿐이야. 필요한 검증에 시간이 더 든다는 이유로 단계를 생략하지 않아.

노션 기존 조사는 접근 가능한 경우에만 재활용해. 새로운 에이전트가 노션에 접근할 수 없다면 이 문서와 공개 원자료만으로 조사를 진행하고, 노션을 읽었다고 가정하지 않아.

각 조사 단계가 끝날 때 다음 항목을 보고해.

1. 조사한 범위와 실제 확인한 후보 수
2. 통과·탈락·보류된 후보와 근거
3. 공식 자료와 간접 증거의 차이
4. 다음 단계에 필요한 정보
5. 완료한 작업과 완료하지 못한 작업
6. 조사 계획 대비 부족한 부분

**완료하지 않은 단계를 완료했다고 선언하지 않아.**

최종 실험 후보를 확정하기 전에는 각 후보의 평가표를 작성하고, 기존 시장 후보와 비교해 실제로 더 나은 이유를 설명해야 해.

특정 후보에 특별히 좋은 증거가 없다면 일반적인 기술 외주, AI 평가, 앱테크를 선호하는 방향으로 결론을 미리 정하지 않아.

## 8. 최종적으로 받아볼 결과물

최종 보고서에는 각 후보별로 다음을 담을 거야.

- 실제 모집·거래 링크와 확인 날짜
- 지원 가능 여부, 필요 능력, AI 사용 조건
- 첫 입금까지의 절차와 예상 소요
- 첫 달과 반복 운영 시 예상 순수익 범위
- 실질 시간당 순수익 및 근거 수준
- 가장 중요한 실패 요인과 실제 검증 방법

그리고 최소 수입 확보용 1개 + AI 우위 활용용 1개 + 장기적으로 유지할 가치가 있는 후보 1개를 중심으로 조합을 비교하겠어. 세 역할을 하나의 방법이 모두 충족하면 굳이 세 개를 동시에 운영할 필요는 없어.

### v1.1 추가 — 최종 보고서 필수 자료

최종 후보별로 다음 정보를 추가해.

| 항목 | 기록 내용 |
|---|---|
| 후보 식별자 | 플랫폼, 구체적인 모집·서비스·상품 |
| 실제 수요 | 구매 요청·채용공고·거래 증거 |
| 경쟁 상황 | 경쟁자 수·가격대·신규 진입 사례 |
| 고객 확보 | 영업 경로, 시간, 비용, 신규 진입 장벽 |
| 참여 가능성 | 거주 국가·연령·학력·장비·시간 조건 |
| 정산 | 지급 수단, 수수료, 최소 출금액, 지급 지연 |
| 예상 수익 | 비관·기준·낙관 시나리오와 계산 근거 |
| 근거 수준 | A/B/C/D/미확인 |
| 단계 상태 | 검증 A~E 중 어디까지 통과했는지 |
| 실패 요인 | 선발 탈락, 수요 부족, 고객 확보 실패 등 |

점수표와 후보 순위는 이 자료에 근거하여 작성해.

근거가 부족한 후보를 그럴듯한 추정값으로 포장하지 않아.

## 9. v1.1 신설 — 이전 조사 기록 인계 및 재사용 규칙

새로운 에이전트는 아래 기록을 **검증이 완료된 분석 결과가 아닌 예비 조사 자료**로 취급해.

### 9-1. 이전 조사 이력

**1차 조사**

AI 평가 플랫폼, 기술 외주, 재택 업무 대행, 잠실 단기 알바에 대한 초기 조사.

대표적인 탐색 대상은 Outlier, DataAnnotation, OneForma, Prolific, 크몽 Discord 봇 제작, Notion 자동화, 잠실 지역 구인공고 등이었어.

재사용 가능한 것은 구체적인 플랫폼 이름·공고 URL·조사 키워드와 재검증할 가설이야.

**2차 조사**

Roblox Creator Store, CrowdGen, PlaytestCloud, 국내 설문 서비스, 디지털 상품 시장 등으로 조사 영역 확대.

8개 영역에 걸쳐 48개 후보 목록을 제시했지만, 플랫폼과 추상적 서비스 아이디어가 섞여 있었어.

따라서 이 48개는 검증 완료 후보 수로 인정하지 않아.

당시 작성한 20개 기본 검증 목록 역시 모든 후보가 필수 조건을 통과했다는 근거로 사용하지 않아.

**3차 조사**

AI 플랫폼의 정산 주기, 기술 외주 수수료, 일부 거래 후기, Roblox Creator Store 정산 조건 등을 추가 조사.

실제 검토할 항목을 발견한 자료로 활용할 수 있지만, 개별 후보의 자격·정산·신규 진입 가능성을 최종 검증한 것으로 인정하지 않아.

**4차 조사**

Discord 봇 오류 수정 서비스를 39,000원에 판매하는 상품을 우선 제시했어.

그러나 실제 구매 수요와 신규 판매자의 진입 가능성, 고객 확보비용, AI 생산성 우위를 충분히 검증하지 못했어.

따라서 이 상품과 가격은 **확정안이 아니며, 우선순위도 무효**야.

Discord 봇 수정 자체를 탐색 범위에서 제거할 필요는 없지만, 처음부터 우선 추천 후보로 지정하지 않아.

### 9-2. 인계 가능한 정보의 범위

이전 조사에서 발견한 플랫폼, 공고 식별자, 공식 정책 URL, 시장 조사 키워드, 실패 사례는 검색의 출발점으로 사용할 수 있어.

반면 다음 사항은 이전 결과를 그대로 믿지 않고 다시 검증해.

- 공고가 현재 활성 상태인지
- 국내 거주자가 현재 가입하고 정산받을 수 있는지
- 자격 요건이 바뀌었는지
- 공식 정책과 실제 지급 과정이 일치하는지
- 판매 후기와 거래 건수가 실제로 확인되는지
- 신규 진입자의 첫 구매 가능성이 있는지
- 이전에 제시된 예상 수익과 작업시간이 타당한지
- 경쟁 상황이 이전 조사와 달라졌는지

과거 조사에서 제시된 웹 검색 인용 식별자는 새로운 에이전트가 접근할 수 없는 경우 근거로 사용하지 않아. 원본 URL을 다시 찾아 검증해야 해.

### 9-3. 현재 인정되는 조사 진행 상태

| 계획 단계 | 현재 판정 |
|---|---|
| 1. 40~60개 후보 발굴 | 예비 목록 존재, 유효 후보 수 재산정 필요 |
| 2. 15~20개 기본 검증 | 완료 인정 불가 |
| 3. 6~8개 심층 분석 | 완료 인정 불가 |
| 4. 3~5개 실험 후보 확정 | 완료 인정 불가 |
| 검증 D: 실제 지원·판매 | 미실행 |
| 검증 E: 첫 유료 거래·정산 | 미실행 |

새로운 에이전트의 출발점은 **1단계 후보 발굴 자료의 재검토**야.

이미 검증된 근거는 재사용할 수 있지만, 기존에 발표된 후보 개수나 순위를 그대로 이어받아 2단계 완료 상태에서 시작하면 안 돼.

## 10. v1.1 신설 — 새로운 에이전트의 독립 실행 지침

### 10-1. 사용자에 대해 확정적으로 알고 있는 조건

- 한국에서 실제 현금 수익을 얻고자 함.
- 성인이면서 고등학교 재학 중임.
- 월 용돈은 약 5만 원이며 AI 사용 비용을 보충할 수익이 필요함.
- 월 순수익 5만~50만 원이 주요 목표이고 상한은 100만 원 미만.
- 실제 가용시간은 미확정이므로 주 2~6시간을 우선 비교 기준으로 사용.
- 재택 인터넷 기반 업무를 우선하며, 잠실새내역에서 이동 가능한 일자리도 허용.
- AI 도구 활용 경험이 있고 소프트웨어 개발·자동화 분야의 개인 프로젝트 경험이 있음.
- 구체적인 보유 자격, 장비, 외주 경력, 영어 능력, 판매 실적은 확인되지 않은 부분을 별도로 검증해야 함.
- 기존 조사를 수행했던 AI의 추천이나 판매 상품은 사용자의 최종 선택으로 확정되지 않았음.

### 10-2. 조사 재개 절차

1. 이 계획서의 평가 기준과 게이트를 먼저 적용한다.
2. 이전 조사 자료에서 직접 검증 가능한 후보만 회수한다.
3. ① AI 평가·데이터 작업, ② 소규모 기술 외주, ③ 재택 업무 대행을 먼저 깊게 조사한다.
4. ④ 잠실새내 기준 단기 알바를 현실적인 수익 비교군으로 유지한다.
5. 이 네 영역을 확인한 뒤 나머지 시장으로 확장한다.
6. 필요한 근거가 부족한 경우 새로운 후보를 조사하되, 실적을 만들기 위해 후보 수를 채우지 않는다.
7. 자격·정산·수요·경쟁 검증을 거친 후보만 점수 모델에 진입시킨다.
8. 모든 조건을 통과한 뒤에만 3~5개 수익 실험을 설계한다.

### 10-3. 금지할 진행 방식

- 플랫폼에 가입할 수 있다는 이유만으로 실제 수익 가능성을 확정하지 않는다.
- 판매자가 존재한다는 이유만으로 시장 수요를 입증했다고 하지 않는다.
- 기존 판매자의 실적을 신규 판매자의 예상 매출로 사용하지 않는다.
- 확인되지 않은 고객 확보 확률이나 작업 배정 확률을 임의로 작성하지 않는다.
- AI를 사용할 수 있다는 사실만으로 경쟁 우위를 인정하지 않는다.
- 충분한 조사 없이 특정 외주 상품이나 판매 가격을 확정하지 않는다.
- 조사 단계에서 사용자 승인 없이 지원·계약·유료 결제·상품 공개를 실행하지 않는다.
- 추가 조사를 계속하는 대신, 충족된 게이트와 미충족된 게이트를 분명히 보고한다.

### 10-4. 사용자에게 전달할 중간 보고

조사를 계속할 때마다 다음 형식을 사용해.

**현재 조사 단계:** 1~4단계 중 어느 단계인지

**검증된 내용:** 근거가 있는 새 정보

**탈락·보류된 후보:** 판단에 영향을 준 이유

**남은 검증:** 아직 확보하지 못한 필수 정보

**다음 작업:** 계획서에 따라 진행할 조사

실험 후보가 정해지기 전에는 확정적인 상품 홍보문이나 판매 계획을 작성하는 것보다 근거 확보에 우선순위를 둬.

이번에는 검증 A의 일부와 공개 자격·수수료 조사를 수행했고, 검증 C(직접 작업 재현), D(실제 지원·고객 반응), E(현금 정산)는 진행하지 않았어. 실제 지원·판매 게시·유료 결제 역시 수행하지 않았어.
