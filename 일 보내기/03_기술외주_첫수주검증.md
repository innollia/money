# 03 기술 외주·첫 수주 검증

## 그대로 전달할 프롬프트

https://github.com/innollia/money 최신 main의 README.md, AGENTS.md, 문서/실행기준_v1.2.md, 자료/원본_v1.1_과거실사.txt, 보고서/제출규격.md를 읽고 작업하라. 사용자가 커넥터다. 다른 에이전트를 부르거나 자동 보고하지 마라.

목표: 구글시트/n8n의 작은 오류 수정 및 Discord 봇 수정에서 신규자가 비용을 거의 들이지 않고 첫 거래를 시험할 경로가 있는지 판단한다. 판매 상품을 더 찾는 것이 목적이 아니다.

1. 원문 2차 실사의 실제 구매 요청을 출발점으로 현재 활성 여부·요구 범위·제시 예산·경쟁·채용 표시·입찰 비용을 확인한다. 표시 예산은 낙찰액이나 실제 지급이 아니다.
2. 소규모 구매자 직접 의뢰 최대 5건, 신규/저실적 판매자 실제 계약 사례 최대 2건, 실패·미수주 사례 최대 2건을 조사한다. 확보 실패도 결과다. 같은 출처 복제·자기 광고를 독립 근거로 세지 않는다.
3. 신규 진입 정의(가입 기간/완료 계약 수 등)를 자료에 맞게 명시한다. 신규 여부를 모르면 미확인. 사례 수로 성공률을 계산하지 않는다. 실패 사례의 분모·선택편향도 명시한다.
4. Upwork 입찰 자원·수수료·출금 비용과 Freelancer 초기 잔액 조건은 공식 해당 조항으로 확인한다. 무료 제공을 가정하지 않는다. 계정별 잔액은 사용자 확인 필요. 유료 입찰은 하지 않는다.
5. 유료 수요·실행 가능성·진입 경로가 확보되면 가장 작은 1건의 비공개 제안 초안, 범위/납품 기준/상한 공수/중단 조건을 작성한다. C 재현 전 확정 가격 금지. 실제 상품 제작·공개 게시·고객 연락·지원은 하지 않는다.
6. 근로 기준선 보고서가 이미 있으면 읽어서 비교하되 수정하지 않는다. 없으면 비교 대기라고 쓰고, 0/1/2건 수주 시 조건부 순수익과 영업 포함 시간을 계산 가능한 범위만 제시한다. 근거 없는 성공확률 금지.

공수 상한: 이번 차수 90분. 신규 진입 증거가 끝내 없으면 시장 수요 확인·신규 진입 미검증으로 보류하고 종료한다. 차별화 상품 아이디어로 실패를 덮지 않는다.

완료 조건: 현재 수요·신규 진입·지원 비용 판정, 실제 다음 행동 1개 또는 명확한 보류 사유. 최종 추천 상품이나 39,000원 가격을 임의 확정하지 않는다.
