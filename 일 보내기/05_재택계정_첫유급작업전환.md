# 05 재택 계정·첫 유급 작업 전환

상태: 계정 상태 입력 후 전달. 01~04 반복 조사 금지. 사용자가 계정 가입을 진행 중이며 오프라인 알바는 최대한 후순위다.

## 사용자 전달 시 덧붙일 비민감 값

플랫폼명: __ / 상태: 가입중·가입완료·심사중·활성·대기열 / 현재 모집 또는 유급 작업 표시: 있음·없음·미확인.

전부 가입 완료할 필요 없음. 먼저 확인 가능한 플랫폼 1개로 시작한다. 미확인 숫자는 비워 둔다. 로그인 정보·개인 식별값·비공개 업무 내용은 첨부하지 않는다.

## 그대로 전달할 프롬프트

https://github.com/innollia/money 최신 main의 README.md, AGENTS.md, 문서/실행기준_v1.3.md, v1.2, 보고서/02_재택AI작업.md·03_기술외주.md·04_현실실험설계.md를 읽고 작업하라. 최신 사용자 정정이 과거 매머드 우선 권고보다 우선한다. 사용자가 커넥터다. 재위임·자동 연락 금지.

목표: 사용자가 방금 가입/접근한 재택 플랫폼 1개에서 다음 유급 작업 접근 단계로 실제 전환할 수 있도록 구체화한다. 가입 자체나 조건부 초안만으로 수익 검증을 완료했다고 쓰지 않는다.

1. 위 입력을 읽고 계정 상태·현재 모집·필수 자격·심사/시험·공개된 보수/단위·최소시간·한국 지급·AI 도구 허용을 분리한다. 사용자가 확인해 준 값과 담당자가 직접 읽은 공식 원문을 구별한다. 계정 접근 도구/승인이 없으면 로그인 화면을 봤다고 쓰지 않는다.
2. 자격을 막는 조건부터 확인한다. Outlier 고교 재학 적용 예외는 가입 완료만으로 충족되지 않는다. OneForma는 해당 프로젝트 실제 단가/지급주기를 일반 도움말로 대체하지 않는다. Prolific 대기열·Upwork 잔액은 각각 유급 배정·수주와 다르다.
3. 계정에 접근하지 못해 꼭 필요한 값이 빠졌으면 최대 3개의 다음 확인 질문을 만든다. 메뉴명은 실제 확인/추정을 구별한다. 입력 없이 과거 02~04 보고서 전체를 재작성하지 않는다.
4. 자격/지급 경로가 확인되고 실제 유급 모집·작업이 열렸다면 그 **특정 항목 1개**의 다음 클릭/준비/승인 범위를 작성한다. 지원서가 필요하면 확인된 사실만으로 비공개 초안을 완성하고, 사용자 경력을 만들지 않는다. 비공개 시험 문제를 대신 풀거나 금지된 AI 작업을 수행하지 않는다.
5. 제안 시간은 학교·통학·고정 일정과 분리한 10~20분 비동기 블록으로 한다. 이는 실제 가용시간 약속이 아니다. 개인 일정은 주 에이전트가 확인한 제약만 적용하고 Notion 전체를 읽거나 공개 저장소에 시간표를 복제하지 않는다.
6. 계정 대기/작업 0/자격 불일치면 보류 이유와 재개 신호를 하나씩 남긴다. 다른 계정 입력이 있으면 그중 확인 가능한 1개로 전환한다. 입력 없는 신규 플랫폼 탐색·유료 결제·오프라인 알바 문의로 우회하지 않는다.

범위: 확인·초안·다음 단계 준비. 실제 외부 지원·응시·고객 연락·결제·계약·지급 연결 대행은 별도 사용자 지시 없으면 수행하지 않는다. 사용자가 직접 진행한 가입/지원은 자기보고로 기록할 수 있다. 승인된 일을 다시 승인받게 만들지 말고 실제 승인 범위를 확인한다.

공수 상한: 30분. 계정 입력을 기다리는 시간을 실제 활동시간과 분리 기록. 보고서에는 수행한 실제 작업·막힌 값·다음 행동만 적고 수익 기대 확률/확정 시급을 만들지 않는다.
