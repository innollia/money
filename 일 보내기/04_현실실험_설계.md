# 04 현실 실험 설계

상태: 전달 가능(2026-10-18). 01~03 보고서 회수·주 에이전트 검토 완료. 실제 외부 행동 승인은 아님.

## 전달 시 사용할 프롬프트

https://github.com/innollia/money 최신 main의 README.md, AGENTS.md, 문서/실행기준_v1.2.md, 문서/01차_보고서회수_검토.md, 원본 자료, 보고서/01~03 결과와 제출규격을 읽어라. 선행 보고서가 없으면 선행 자료 미수신으로 보고하고 재조사를 시작하지 마라. 사용자가 커넥터이며 자동 재위임하지 않는다.

목표: 이미 확보한 사실로 승인 가능한 최소 현실 실험을 설계한다. 공개 검색을 반복하지 않는다. 보고서 충돌이 실제 선택을 바꿀 때에만 원본을 제한 확인한다.

이번 구체적 우선순위:

1. 매머드의 주 1일·기간·재학생·유급시간·첫 지급 문의를 첫 행동으로 준비한다. 보고서상 마감 10/22는 담당자 확인값이며 전송 당일 모집 상태 확인을 카드에 넣는다. 리베는 매머드 조건 불가일 때의 대안. 두 곳 모두 실제 연락 금지.
2. 사용자에게 필요한 답을 하나의 짧은 양식으로 묶는다: 근로 문의 진행 의향, 가능한 요일·근무/왕복이동 포함 시간·지속 가능 기간, 기존 OneForma/Prolific/Upwork 계정 유무. 계정이 있는 서비스만 다음 화면 확인을 요청한다. Outlier 전문학사 보유를 기본 질문으로 되풀이하지 않는다. 고교 재학 조건과 학력 예외 미확인을 유지한다.
3. 보고서의 A/B 등급을 재사용하지 말고 원문/색인/후기 및 직접 열람 여부로 표시한다. 색인·과거 계약을 오늘 열린 의뢰나 수입으로 바꾸지 않는다. OneForma 지급 충돌은 계정 확인 필요로 유지한다.
4. 외주 재현 제작·유료 입찰·신규 가입을 당장 할 일로 추가하지 않는다. 근로 문의 이후 조건이 맞지 않으면 기존 계정 확인으로 넘어가는 분기를 작성한다.
5. 사용자 답이 아직 없어도 문의 초안·조건부 카드·회수 양식은 끝낸다. 사용자 답이 필요한 곳은 미확인으로 남긴다. 문서 준비 완료와 실험 준비 완료를 구분한다.

- 준비 완료 후보 최대 3개를 비교하고 가장 먼저 할 1개를 고른다. 하나도 준비되지 않았으면 막는 질문과 필요한 사용자 입력만 정리한다.
- 후보마다 A~E 및 경쟁 게이트의 통과·미확인을 보존한다. 미확인 B를 D 승인으로 덮지 않는다.
- 카드: 대상/정확한 실행 행동/필요한 비민감 입력/승인 범위/시간·현금 상한/실행 순서/성공·실패·중단 조건/관측 기록/첫 지급 확인 절차.
- 예상 매출·작업 완료·현금 입금을 구분한다. 수입 0 및 전체 영업시간도 측정한다. 근로 기준선보다 낮을 때의 유지/중단 판단을 넣는다.
- 사용자에게 보여줄 승인 요청은 실제 문의·지원·게시 초안과 함께 작성한다. 외부 전송·가입·인증·지원·게시·결제·계약 자체는 수행하지 않는다.

공수 상한: 45분. 시작·종료 시각과 실제 활동 시간을 기록한다. 최종 추천 전체 탐색 완료로 과장하지 않는다. 새 시장 조사 및 반복 공개 검색은 이번 범위가 아니다.
